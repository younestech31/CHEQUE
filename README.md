# CHEQUE Desktop

تطبيق مكتبي محلي على Windows لإدارة الشيكات والتحصيل الفعلي للخزينة وتصنيف المبالغ حسب المرقين العقاريين والتجميد والتحويلات.

## المعمارية
- Tauri 2 + Rust
- React + TypeScript + Vite
- SQLite محلية في مجلد بيانات التطبيق
- واجهة عربية RTL
- تخزين المبالغ كأعداد صحيحة بالسنتيم (100 سنتيم = 1 دج)

## قواعد العمل
1. تسجيل الشيك لا يتطلب تحديد المرقي.
2. تسجيل الإيداع لا يزيد رصيد الخزينة.
3. لا يصنف المبلغ إلا بعد تأكيد دخوله فعلياً من قيد دائن في كشف حساب الخزينة.
4. يمكن تأكيد القيد البنكي على دفعات، ولا يتجاوز مجموع التحصيلات قيمته الدائنة.
5. يمكن ربط التحصيل بأكثر من شيك وربط الشيك بتحصيلات متعددة مع حفظ المصدر.
6. يمكن توزيع التحصيل المؤكد على عدة أسطر تخص زبائن أو مرقين مختلفين.
7. كامل المبلغ المحصل والمصنف مستحق للمرقي، ولا يتجاوز مجموع التصنيف قيمة التحصيل.
8. لا يقبل المشروع إلا إذا كان تابعاً للمرقي المحدد.
9. التجميد لا يغير رصيد الخزينة.
10. إعداد التحويل لا يخصم الرصيد؛ التنفيذ الفعلي فقط ينشئ حركة خارجة.
11. يمنع تجاوز مبلغ التحصيل أو التخصيص أو الحجز أو السيولة.
12. لا تحذف الحركات المالية؛ التصحيح بقيود عكسية موثقة.

## ما تم تنفيذه
- شاشة تسجيل الشيكات والإيداعات دون طلب المرقي.
- إدخال قيود كشف الحساب الدائنة والمدينة وتأكيد التحصيل الجزئي أو الكلي.
- مطابقة مرنة بين الشيكات والتحصيلات.
- تسجيل حركة الخزينة الداخلة عند تأكيد التحصيل فقط.
- قائمة التحصيلات المؤكدة التي تنتظر التصنيف.
- إضافة الزبائن والمشاريع وربط المشروع بمرقيه.
- تصنيف التحصيل إلى عدة أسطر مع حد إجمالي يمنع تجاوز التحصيل.
- قائمة مستقلة لكل مرقٍ تعرض الزبون والمشروع ونوع العملية والمبلغ.
- تجميد جزئي على مستوى سطر الاستحقاق مع سبب وتاريخ ورفع موثق، دون التأثير على رصيد الخزينة.
- إنشاء تحويل دوري أو استثنائي، وحجزه بعد التحقق من المستحق والسيولة، ثم تسجيل التنفيذ الفعلي وحده كحركة خارجة.
- منع تعديل تفاصيل التحويل بعد الحجز، ومنع التجميد فوق المبالغ المحجوزة أو المنفذة.
- إنشاء نسخ احتياطية محلية من قاعدة SQLite وفحص سلامتها قبل اعتمادها.
- إعادة فحص النسخ الموجودة بوضع القراءة فقط عبر `integrity_check` و`foreign_key_check`، دون تعديل النسخة.
- تقرير مالي تفصيلي حسب المرقي مع فصل المستحق والتجميد والحجز والتنفيذ والمتاح على مستوى كل تخصيص.
- تصدير التقرير إلى CSV بترميز UTF-8 وفتح مباشر في Excel، والطباعة أو الحفظ بصيغة PDF عبر نافذة الطباعة.
- ترحيلات قاعدة بيانات مرقمة ومطبقة داخل معاملات ذرية.

## التطوير على Windows
يتطلب Node.js 20+ وPython 3 وRust toolchain وتهيئة Tauri 2. ينشئ أمر Tauri أيقونات التطبيق تلقائياً قبل التشغيل أو البناء.

```powershell
npm install
npm run tauri dev
```

## اختبارات قاعدة البيانات
```powershell
python scripts/test_schema.py
python scripts/test_workflow.py
```

## الحالة
تم تنفيذ تسجيل الشيكات والتحصيل والتصنيف وقوائم المرقين والتجميد والتحويلات والتقارير والنسخ الاحتياطي والفحص. نجح بناء Rust وواجهة TypeScript/Vite وإنشاء مثبتَي Windows (MSI وEXE) في CI للنسخة السابقة `8d9cbcd`. أضيف بعد ذلك الترحيل الخامس واختبارات إضافية لحماية تفاصيل التحويل؛ هذه التغييرات اللاحقة لم يُتحقق بعد من نجاح CI وبناء Windows لها. لم تنفذ استعادة النسخة الاحتياطية، ولم يجر اختبار التثبيت والتشغيل على جهاز Windows فعلي. لذلك لا تعتمد البرنامج على بيانات مالية تشغيلية قبل نجاح البناء الأحدث واختبار التثبيت وسيناريوهات العمل والاستعادة على الجهاز المستهدف. كما أن مطابقة رصيد الخزينة مع كشف البنك غير مكتملة حالياً: لا يوجد إدخال معتمد للرصيد الافتتاحي ولا تسوية للقيود المدينة الخارجية أو ربطها بالتحويلات المنفذة؛ لذلك قد لا يعكس الرصيد المتاح في التطبيق الرصيد البنكي الفعلي. هذه فجوة مالية مانعة للاعتماد التشغيلي، وتتطلب استكمال التسوية واختبارها قبل استعمال التحويلات.


## تسوية الخزينة مع كشف البنك — الترحيلان 6 و7

- يجب تسجيل رصيد بداية اليوم من كشف الحساب مرة واحدة مع التاريخ والمرجع.
- يعتمد رصيد الخزينة والحجز على الرصيد الافتتاحي مضافاً إليه الحركات المؤرخة في ذلك اليوم وما بعده؛ الحركات الأقدم لا يعاد احتسابها.
- كل قيد مدين في كشف الحساب يحتاج تسوية: مطابقته كلياً أو جزئياً مع تحويل منفذ (دون خصم ثانٍ)، أو تسجيله كخصم خارجي كامل، مع رفض مطابقة تحويل بتاريخ تنفيذ لاحق لتاريخ القيد البنكي (ويُرحّل مرة واحدة إلى دفتر الخزينة).
- يمنع النظام تجاوز مبلغ القيد المدين، أو مطابقة تحويل بأكثر من قيمته المنفذة، أو تكرار الخصم الخارجي.
- تسويات القيود المدينة والرصيد الافتتاحي سجلات غير قابلة للتعديل أو الحذف؛ التصحيح يحتاج مساراً محاسبياً عكسياً منفصلاً.
- تظهر حالة الرصيد الافتتاحي والتنبيه في لوحة القيادة، وتظهر مبالغ التسوية والمتبقي لكل قيد مدين في شاشة الخزينة.

**قيد مهم:** هذه الإضافات أصبحت في قاعدة البيانات والواجهة، لكن لا تعتمدها تشغيلياً قبل نجاح اختبارات CI والبناء وفحص دورة كشف حساب فعلية. كما أن الخصم الخارجي لا يقبل حالياً إلا تسوية القيد كاملاً في عملية واحدة؛ أما المطابقة مع تحويل منفذ فتدعم المبالغ الجزئية.
